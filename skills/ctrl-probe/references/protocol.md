# 수집기 해석 범위

이 문서는 함께 배포한 `scripts/observe.py`가 처리하는 범위를 설명합니다. 실제 장비의 규격 적합성·원인 판정은 해당 작업의 규격·실행 중 바이너리·입력 조건과 대조합니다.

- classic pcap의 Ethernet/VLAN, Linux cooked v1/v2, raw IPv4를 읽습니다. pcapng·IPv6·IP fragment 재조립은 지원하지 않습니다.
- 사용자가 지정한 두 장비와 TCP 포트를 사용해 방향을 구분합니다. 분할·병합·재전송·순서 역전을 재조립하고, gap·충돌 overlap·잘린 패킷을 별도로 남깁니다.
- 현재 디코더는 `7f7f` 시작값, 2바이트 길이·대상·opcode와 CRC16을 읽습니다. CRC 불일치 프레임은 원문을 보존하고 필드 해석을 보류합니다.
- opcode `0x23`과 payload 224바이트가 함께 맞을 때만 status/NOCC/OCC/VOL/DS/SFR/SMT를 각 32바이트로 표시합니다. 다른 형식은 원문 바이트를 남깁니다.
- 비교 결과는 같은 수집 구간의 순서에 따른 차이 후보입니다. 같은 설정·물리 입력·집계 구간과 사건 대응은 별도로 확인합니다.
- 패킷이 없거나 일부만 수집된 상태를 장비 고장으로 바꾸어 판정하지 않습니다. 통신 프로세스·시각·실행 세대·유실 상태를 함께 봅니다.

프로세스와 패킷 관측만으로 제어기 내부 처리·화면 표시·물리 등화까지 정상이라고 확정하지 않습니다. 그 경계의 관측이 필요한 때 해당 도구를 추가합니다.
